Train a neural LLM → the real way

This page trains a small transformer, the same kind of model as GPT, from random numbers. It cuts text into tokens, measures how surprised the model is by each next token (the cross-entropy loss), and uses backpropagation and gradient descent to make it less surprised. Then you can distill it into a smaller model. Everything runs on your computer, in your browser.

New to this? Read the lesson on cross-entropy and compression first, or just start below.

    Pre-train it: gradient descent on the cross-entropy loss

    Each step takes a batch of random pieces of the training text. For every position, the model gives a probability to every possible next token. The loss is the average of −log₂(probability of the token that really came next). Backpropagation finds how each weight changes the loss, and the AdamW optimiser moves every weight a little bit downhill. The learning rate warms up, then slowly drops (cosine schedule).

    In distillation, a small student model learns from the big teacher you just trained. Instead of only learning the one token that really came next, the student learns the teacher's whole probability distribution, using the cross-entropy between the two distributions as its loss. That gives it much more information per token.

    The lesson: cross-entropy, compression and training

    1. Information: rare things cost more bits

    Imagine sending instructions to a far-away robot: up, down, left, right. If "up" is sent half of the time, "down" a quarter of the time, and "left" and "right" an eighth each, the best code uses 0 for up, 10 for down, and 110 and 111 for left and right. Each symbol costs −log₂(its probability) bits: 1, 2, 3 and 3. Claude Shannon called this number the information of an event. It is how many times you must halve 1 to get down to the probability. The average, Σ p·(−log₂ p), is the entropy: the best possible number of bits per symbol.

    2. Cross-entropy: using a code made for the wrong world

    Now the plan changes: right is sent half of the time, left a quarter, up and down an eighth each. The robot still uses the old code. The average cost becomes a weighted sum: the new probabilities p times the old code lengths −log₂ q. That sum, H(p, q) = Σ pᵢ · (−log₂ qᵢ), is the cross-entropy. In the diagram, each bar's width is pᵢ and its height is −log₂ qᵢ, so the total area is the cross-entropy. The dashed outline is the best you could do, the entropy of p.

    3. The key fact: the minimum is when q = p

    Keep the real world p fixed and change the code q. Cross-entropy is lowest when q is exactly p, and that lowest value is the entropy of p. Move the slider to change p. The purple curve is H(p, q) for every q; the green curve traces where its minimum goes, which is the entropy.

    4. Why this trains language models

    A language model is a function: it reads tokens and gives a probability q to every possible next token. For each position in the training text we look at the token that really came next and take −log₂ q(that token): how surprised the model was. The loss is the average. That is the cross-entropy between the true patterns of language (p, as sampled by the text) and the model (q). Because cross-entropy is smallest when q = p, pushing the loss down with gradient descent pushes the model's beliefs towards the real patterns of language. The loss can never go below the entropy of the text itself.

    It is also compression. With a technique called arithmetic coding, a model that gives probability q to each next token can store the text in about Σ −log₂ q bits. So the loss in bits per token is exactly how well the model would compress the text. Training a language model is training a compressor. That is why step 3 compares your model with gzip: once its validation loss drops below gzip's line, your neural network is a better compressor of new text than gzip.

    5. Language trees and zipping

    A 2002 paper, Language Trees and Zipping, found which languages are related using only gzip. Take two texts A and B. Add a small piece b of B to the end of A, and compress. The extra bytes tell you how well a compressor tuned to A handles b: a rough, practical estimate of cross-entropy. If b is like A, it costs few extra bytes.     6. Distillation and KL divergence

    When you distill a big model into a small one, the "true" distribution p is the teacher's whole prediction, not just one real token. The student's loss is the cross-entropy H(pteacher, qstudent). The difference between cross-entropy and its smallest possible value is the Kullback–Leibler (KL) divergence: DKL(p ‖ q) = H(p, q) − H(p). It is the number of bits per symbol you waste by using a code made for q. For the robot, that is 2.625 − 1.75 = 0.875 bits. It is 0 when q = p and grows as they differ, but it is not symmetric: DKL(p ‖ q) ≠ DKL(q ‖ p).

    Puzzle 1: show that Σ pᵢ log(pᵢ / qᵢ) is the same as H(p, q) − H(p).

    log(pᵢ / qᵢ) = −log qᵢ − (−log pᵢ). Multiply by pᵢ and add up: Σ pᵢ(−log qᵢ) − Σ pᵢ(−log pᵢ) = H(p, q) − H(p). The short form hides that it is a difference of two averages.

    Puzzle 2: how does the diagram show the KL divergence?

    In the cross-entropy diagram, each bar has width pᵢ. Its height is −log₂ qᵢ, and the dashed outline is at −log₂ pᵢ. The gap between them is log₂(pᵢ / qᵢ), so the total area of the gaps (counting gaps below the outline as negative) is Σ pᵢ log₂(pᵢ / qᵢ), the KL divergence. It is never negative in total, even though single bars can be.

    Puzzle 3: what happens if you distill with the KL divergence instead of cross-entropy?

    Nothing changes in the training. KL = cross-entropy − H(pteacher), and the teacher's entropy does not depend on the student's weights. So both losses have exactly the same gradient, and gradient descent makes exactly the same steps. Only the number you see is different: KL reaches 0 when the student matches the teacher perfectly, while cross-entropy bottoms out at the teacher's entropy. Try it in step 5: run once with each loss, and compare the student's curves.

    What is inside this model?

    A decoder-only transformer, like GPT-2: token and position embeddings, then a stack of blocks. Each block has LayerNorm, causal multi-head self-attention (each token looks back at earlier tokens), a residual connection, LayerNorm, a two-layer MLP with GELU, and another residual connection. A final LayerNorm and an output layer (sharing weights with the token embeddings) give one score per vocabulary token, and softmax turns the scores into probabilities. Every layer has a hand-written backward pass, based on Andrej Karpathy's llm.c. The optimiser is AdamW (β₁ = 0.9, β₂ = 0.95) with gradient clipping at 1.0. It runs on your CPU in a Web Worker, so it is small: real LLMs use the same recipe with billions of weights, trillions of tokens and thousands of GPUs.
